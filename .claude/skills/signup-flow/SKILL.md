# 회원가입 플로우

이메일 + 비밀번호로 가입하는 **가입 화면과 가입 방식**만 다룬다. 로그인 화면, 소셜 로그인, 비밀번호 찾기, 가입 후 서비스 화면은 이 스킬의 범위가 아니다(가입 화면에서 로그인으로 넘겨주는 연결만 다룬다).

## 0. 시작 전에 확인할 것

1. **브랜드 슬롯**(아래 1장)을 채운다. 브랜드 디자인 문서(`<brand>.md` 등)가 있으면 거기서 값을 가져오고, 없으면 사용자에게 브랜드명과 대표색 하나만 묻고 나머지는 계산한다.
2. 화면 문구·예시·약관 이름에 **다른 브랜드 이름이 남아 있지 않은지** 검사한다. 예전 레퍼런스 브랜드명, 예시 도메인(`@○○.gg`), 로고 문자열, 예약 닉네임 목록까지 본다. 남아 있으면 브랜드 슬롯 값으로 바꾸거나 지운다.
3. 백엔드가 있으면 6장 계약에 맞춰 연결하고, 없으면 같은 계약을 브라우저 저장소로 흉내 내는 DEMO 모드로 만든다.

## 1. 브랜드 슬롯 — 여기만 바꾸면 다른 브랜드가 된다

화면 코드에는 브랜드 값을 직접 쓰지 않는다. 문구는 `{{…}}` 자리표시자로, 색은 아래 CSS 변수로만 참조한다.

| 슬롯 | 예시 | 쓰이는 곳 |
|---|---|---|
| `{{BRAND}}` | `Acme` | 로고, 약관 이름, 완료 문구 |
| `{{BRAND_KO}}` | `에이크미` | 한글 문구 |
| `{{MEMBER}}` | `회원` / `플레이어` / `크리에이터` | "○○ 정보 입력", "○○님" |
| `{{EMAIL_EXAMPLE}}` | `name@example.com` | 형식 오류 예시 |
| `{{RESERVED}}` | `admin, 운영자, {{BRAND}} 소문자` | 예약 닉네임 |
| `{{MIN_AGE}}` | 한국 서비스 `14` | 약관 동의 문구, 연령 확인 |

```css
:root{
  /* 브랜드 — 바꿔 끼우는 값 */
  --brand-primary: #3B5BFF;      /* 대표색 하나 */
  --brand-primary-hover: #6680FF;
  --brand-on-primary: #FFFFFF;   /* 대표색 위 글자. 대비 4.5:1 이상 */
  --brand-tint: rgb(59 91 255 / .14);
  --font-display: system-ui, sans-serif;  /* 제목·버튼 */
  --font-body: system-ui, sans-serif;     /* 본문·입력 */
  --radius: 8px;                 /* 브랜드 모서리 성향 */

  /* 상태색 — 브랜드가 바뀌어도 의미는 고정 */
  --ok: #1F9D6B;  --err: #E5484D;  --err-bg: #FDECEC;

  /* 면·글자·선 — 라이트/다크는 브랜드가 정한다 */
  --bg: #FFFFFF; --bg-input: #F6F7F9; --text: #111; --text-sub: #666;
  --text-placeholder: #9A9A9A; --border: #D9DCE1; --border-focus: var(--brand-primary);
}
```

- 강조색은 대표색 하나만 쓴다. 성공·오류색은 예외다.
- 대표색만 받았으면 hover는 밝기 +15%, tint는 14% 투명도로 만든다. 대표색 위 글자는 대비를 계산해 흰색이나 거의 검정 중 하나로 고른다.
- 효과음, 진행 뱃지, 포인트 연출 같은 **브랜드 연출은 선택 사항**이다. 넣더라도 아래 로직과 타이밍 규칙을 바꾸지 않는다.

## 2. 핵심 원칙 — 오는 사람은 막지 않는다

가입하러 온 사람을 되돌려 보내는 화면을 만들지 않는다. 모든 분기는 "막기" 대신 "다음 길 안내"로 끝낸다.

| 상황 | 막지 말고 이렇게 |
|---|---|
| 이미 가입된 이메일 | 오류가 아니라 안내 카드: "본인 계정 아닌가요?" + `로그인하기`(이메일 채워서 이동) + `비밀번호 찾기` |
| 탈퇴한 이메일로 다시 옴 | 대기 기간 없이 바로 재가입. 환영 문구로 바꾸고 예전 닉네임을 돌려준다 |
| 닉네임이 겹침 | 왜 안 되는지 한 줄 + 추천 버튼으로 바로 다른 이름 |
| 이메일·닉네임 확인 요청이 실패(네트워크) | 진행을 막지 않는다. "확인하지 못했어요"만 표시하고 계속하게 두고, 최종 판단은 가입 버튼을 누를 때 서버가 한다 |
| 연령 기준 미만 | 차단 화면 대신 법정대리인 동의 단계로 보낸다(한국은 만 14세 미만) |
| 필수가 아닌 정보 | 받지 않거나 기본값을 채운다. 국가는 기본값을 미리 선택해 둔다 |
| 가입 버튼에서 서버 오류 | 입력값은 그대로 두고 오류 이유와 다음 행동만 보여준다 |

필수 입력은 **이메일, 닉네임, 비밀번호, 비밀번호 확인, 봇 확인, 필수 약관 동의**뿐이다. 마케팅 수신 같은 선택 항목은 기본으로 체크하지 않고, 가입 버튼의 조건에도 넣지 않는다.

## 3. 비밀번호는 기본으로 숨긴다

이 규칙은 예외 없이 적용한다.

- 비밀번호와 비밀번호 확인 칸은 **처음부터 숨김**(`type="password"`)으로 시작한다. 보이게 시작하지 않는다.
- 각 칸 오른쪽에 눈 아이콘 버튼을 두고, 누른 칸만 보이게 바꾼다. 버튼의 `aria-label`도 "비밀번호 보기" ↔ "비밀번호 숨기기"로 바꾼다.
- 화면을 떠나거나 가입 버튼을 누르면 다시 숨김으로 돌린다.
- `autocomplete="new-password"`를 붙여 비밀번호 관리자가 새 비밀번호를 제안할 수 있게 한다. `off`로 막지 않는다.
- 붙여넣기를 막지 않는다.
- 비밀번호는 어떤 로그·저장소·URL·분석 이벤트에도 남기지 않는다. DEMO 모드에서도 평문 저장은 화면 시연용 테스트 계정에 한정한다.

## 4. 화면 구성 (2단계 + 완료)

```
[1. 계정 만들기]  이메일 · (국가) · 봇 확인 · 필수 약관   → 계속하기
[2. {{MEMBER}} 정보]  닉네임(+추천) · 비밀번호 · 비밀번호 확인   → 가입 완료
[3. 완료]  환영 문구 → 로그인하러 가기 (가입한 이메일을 채워서)
```

레이아웃(모바일 기준):
- 상단: `‹ 뒤로` + 로고(`{{BRAND}}`) → 진행 게이지(3단계, 현재 단계에서 채운 항목 수만큼 실시간으로 채움) → 작은 eyebrow → 제목 → 설명 한 줄
- 입력 영역: 라벨 위·입력칸 아래 도움말. 좌우 여백 20px, 섹션 간격 20px, 라벨↔입력 8px, base unit 4px
- 하단 고정 CTA 하나. 조건을 다 채우기 전에는 비활성
- 입력칸 높이 48~52px, 버튼 높이 52px, 터치 영역 44px 이상

단계별 문구(기본값, 브랜드 톤에 맞게 다듬는다):

| 화면 | eyebrow | 제목 | CTA |
|---|---|---|---|
| 1단계 | NEW {{MEMBER}} | 계정 만들기 | 계속하기 |
| 1단계(재가입) | WELCOME BACK | 다시 오셨군요! | 다시 시작하기 |
| 2단계 | PROFILE SETUP | {{MEMBER}} 정보 입력 | 가입 완료 |
| 완료 | SIGN UP COMPLETE | 가입이 완료됐어요 | 로그인하러 가기 |
| 완료(재가입) | WELCOME BACK | 다시 함께하게 돼서 기뻐요 | 로그인하러 가기 |

## 5. 비즈니스 로직

### 5-1. 이메일 상태
입력값은 `trim().toLowerCase()`로 정규화한 뒤 판단한다.

| 상태 | 조건 | 화면 | 계속하기 |
|---|---|---|---|
| `invalid` | 형식 `^[^\s@]+@[^\s@]+\.[^\s@]{2,}$` 불일치 | 입력을 마친 뒤에만 말풍선 "이메일 형식을 확인해 주세요 / 예: {{EMAIL_EXAMPLE}}" | 불가 |
| `checking` | 형식은 맞고 서버에 묻는 중 | 뱃지 `···` | 불가 |
| `new` | 처음 보는 이메일 | 통과 표시 | 가능 |
| `exists` | 이미 가입됨 | "본인 계정 아닌가요?" 카드 → 로그인 / 비밀번호 찾기 | 불가(로그인으로 안내) |
| `rejoin` | 30일 안에 탈퇴한 이메일 | 환영 카드 + 예전 닉네임 표시, 화면 문구를 재가입용으로 전환 | 가능 |
| `unknown` | 확인 요청 실패 | "확인하지 못했어요" + 다시 확인 버튼 | **가능**(2장 원칙) |

- 서버 확인은 입력이 멈추고 300ms 뒤에 보낸다. 요청마다 순번을 붙이고, 마지막 요청의 응답만 반영한다(늦게 온 옛 응답이 덮어쓰지 않게).
- 같은 이메일의 결과는 캐시한다. 가입·탈퇴가 일어나면 캐시를 비운다.
- 가입 여부를 알려주는 것은 편의를 위한 선택이다. 대신 이메일 존재 여부가 드러나므로 확인 API에 요청 제한을 건다.

### 5-2. 닉네임
| 규칙 | 값 |
|---|---|
| 길이 | 2~12자. 글자 수는 코드 포인트 기준(`[...v].length`) |
| 문자 | 한글 완성형·영문·숫자만(`^[가-힣A-Za-z0-9]+$`). 공백·특수문자·이모지 불가 |
| 자모 | 입력 중인 자모(ㄱ, ㅏ)는 오류로 보지 않고 기다린다. 완성되지 않은 채 제출할 수는 없다 |
| 중복 | 대소문자 구분 없이 하나만 |
| 예약어 | `{{RESERVED}}`는 사용 불가 |
| 보관 | 탈퇴한 사람의 닉네임은 30일 동안 다른 사람이 쓸 수 없다. 같은 이메일로 재가입한 본인만 쓸 수 있다 |

- 형식이 맞을 때만 서버에 중복을 묻는다(입력이 멈추고 250ms 뒤). 결과는 `닉네임|재가입 이메일` 키로 캐시한다.
- 조건은 체크리스트 칩 3개로 보여준다: `2~12자` · `한글·영문·숫자만` · `아무도 안 쓰는 이름`. 입력칸 안에 `n/12` 카운터를 둔다.
- 재가입이면 2단계 진입 시 닉네임 칸에 예전 닉네임을 미리 채운다.
- **추천 버튼**: 닉네임 칸이 비어 있을 때 보인다. 직접 입력하면 숨기고, 추천으로 채운 이름이면 다시 누를 수 있게 둔다. 형용사 + 명사 + (50% 확률로 1~99) 조합, 12자 이내, 예약어 제외. 추천 결과도 같은 중복 확인을 거친다.

### 5-3. 비밀번호
- 조건: 8자 이상 · 영문 포함 · 숫자 포함. 칩 3개로 실시간 체크한다.
- 조건 미달 오류는 칸을 한 번 벗어난 뒤부터 빨갛게 표시한다. 그 전에는 충족한 칩만 초록으로 켠다.
- 비밀번호 확인은 **확인 칸 글자 수가 비밀번호 이상이 되었거나 칸을 벗어난 뒤에만** "비밀번호가 일치하지 않아요"를 보여준다.
- 서버 최소 길이 설정도 8로 맞춰 화면 규칙과 서버 규칙을 같게 한다.

### 5-4. 봇 확인 · 약관 · 국가
- 봇 확인과 필수 약관 동의는 기본 체크 해제. 약관 링크를 눌러도 체크 상태가 바뀌지 않게 한다.
- 약관 문구: "만 {{MIN_AGE}}세 이상이며, {{BRAND}} 이용약관 및 개인정보 처리방침에 동의합니다."
- 국가는 접속 지역(없으면 서비스 기본 국가)으로 미리 채운다. 바텀시트에서 한글·영문 이름으로 검색할 수 있고, 결과가 없으면 "찾는 나라가 없어요"를 보여준다. Esc·배경·닫기 버튼으로 닫는다.

### 5-5. 버튼 활성 조건
- 계속하기: 이메일 `new` · `rejoin` · `unknown` 중 하나 + 봇 확인 + 필수 약관
- 가입 완료: 닉네임 통과 + 비밀번호 조건 통과 + 확인 일치
- 누르면 버튼을 잠그고 "등록 중…"으로 바꿔 중복 제출을 막는다.

### 5-6. 가입 결과 처리
서버가 최종 판단자다. 화면 검사를 통과해도 서버 답을 따른다.

| 오류 코드 | 화면 |
|---|---|
| `nickname_taken` | 닉네임 칸을 중복 오류로 되돌린다(전체 오류 메시지 없이) |
| `exists` | "이미 가입된 이메일이에요 / 로그인 화면에서 로그인해 주세요." |
| `weak_password` | "비밀번호가 너무 쉬워요 / 다른 비밀번호로 바꿔 주세요." |
| `rate_limited` | "잠시 후 다시 시도해 주세요 / 요청이 너무 많아요." |
| `network` | "연결이 불안정해요 / 인터넷 연결을 확인하고 다시 눌러 주세요." |
| 그 밖 | "가입하지 못했어요 / 잠시 후 다시 시도해 주세요." |

- 성공하면 완료 화면으로 간다. 메일 인증이 켜져 있으면 "메일함의 인증 링크를 누르면 로그인할 수 있어요"를 덧붙인다.
- 완료 화면의 `로그인하러 가기`는 가입한 이메일을 채운 로그인 화면으로 보내고 비밀번호 칸에 포커스를 준다.

## 6. 데이터와 서버 계약

화면은 아래 함수만 부른다. 백엔드(Supabase 등)와 DEMO 모드가 같은 함수를 구현한다.

```
checkEmail(email)              → { status: 'new' | 'exists' | 'rejoin', nickname? }
checkNickname(nick, rejoinEmail?) → boolean
signUp({ email, password, nickname, country }) → { ok, needsConfirm?, error? }
```

| 저장소 | 내용 |
|---|---|
| 인증 사용자 | 이메일 + 비밀번호 해시. 인증 서비스가 관리하고 직접 만지지 않는다 |
| `profiles` | id(인증 사용자 FK, 삭제 시 함께 삭제), nickname(길이·문자 CHECK, `lower(nickname)` 유니크), country, created_at |
| `withdrawn_members` | email(소문자, PK), nickname, withdrawn_at. 조회는 30일 이내만 |
| `reserved_nicknames` | 소문자 닉네임 |

- 이메일·닉네임 확인 함수는 `security definer`로 만들고, 익명 사용자에게 실행 권한만 준다. 테이블은 RLS를 켜고 본인 프로필 조회·수정만 허용한다. 탈퇴 보관 테이블과 예약어 테이블에는 클라이언트 정책을 두지 않는다.
- 가입 트리거: 인증 사용자가 생기면 메타데이터의 닉네임·국가로 프로필을 만들고, 같은 이메일의 탈퇴 보관 기록을 지운다. 닉네임이 없으면 임시 닉네임(`member` + id 6자리)을 넣는다.
- 30일 지난 보관 기록은 예약 작업으로 매일 지운다.
- 클라이언트에 넣는 키는 공개용 키(publishable/anon)만이다. 서비스 키는 서버 함수에만 둔다.
- 시연 계정(이미 가입·재가입 시나리오)은 시드 데이터나 대시보드로 만든다.

## 7. 오류를 보여주는 타이밍

| 언제 | 무엇을 |
|---|---|
| 입력하는 동안 | 형식 오류를 띄우지 않는다. 충족한 조건만 켠다 |
| 칸을 벗어나거나 Enter | 형식 오류 말풍선. 고쳐질 때까지 유지 |
| 포인터를 누르고 있는 중 | 말풍선을 띄우지 않고 손을 뗀 뒤 띄운다(레이아웃이 밀려 클릭이 빗나가는 것 방지) |
| 다시 고치기 시작 | 맞아지는 순간 바로 지운다 |
| 서버 확인 중 | `···` 같은 중립 표시만, 오류색 금지 |

오류 말풍선과 서버 오류 영역에는 `role="alert"`를 붙인다. 색만으로 상태를 전달하지 않고 뱃지 문구(`OK` / `ERR`)나 아이콘을 함께 쓴다.

## 8. 하지 말 것

1. 입력 도중에 형식 오류 표시
2. 비밀번호를 보이는 상태로 시작
3. 이미 가입된 이메일을 막다른 오류로 처리(로그인 길을 안내한다)
4. 재가입자에게 대기 기간 강요
5. 확인 API 실패를 이유로 가입 진행 차단
6. 체크박스 기본 체크, 선택 항목을 필수 조건에 포함
7. 브랜드 값을 화면 코드에 직접 쓰기, 다른 브랜드 이름이 남은 채로 납품
8. 대표색 외 강조색 추가
